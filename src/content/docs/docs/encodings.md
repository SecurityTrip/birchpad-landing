## Определение кодировки

При открытии Birchpad проверяет по порядку: метку BOM (UTF-8, UTF-16 LE/BE), корректный UTF-8, UTF-16 без BOM, затем угадывает устаревшую кодировку (Windows-1251, KOI8-R и др.) и, если ничего не подошло, берёт кодировку ANSI — кодовую страницу системы на Windows или значение `files.ansi-encoding`, например `"windows-1251"`.

Кодировка, BOM и концы строк файла сохраняются как были: открыть и сохранить файл без правок — значит получить те же байты.

## Без потерь

- Если файл не декодируется точно, он открывается **только для чтения** с предупреждением и предложением открыть его в другой кодировке. **Редактировать все равно…** показывает все места, где сохранение изменит байты файла.
- Если в тексте есть символы, которых нет в целевой кодировке, сохранение отменяется со списком этих символов — Birchpad никогда не подставляет `?` молча.

## «Кодировать в» и «Преобразовать в»

- **Кодировки → Кодировать в** перечитывает байты файла с диска в другой кодировке — когда файл открылся «кракозябрами». История отмены при этом сбрасывается.
- **Кодировки → Преобразовать в** меняет кодировку, в которой файл будет сохранён. Текст не меняется, а действие отменяется <kbd>Ctrl</kbd>+<kbd>Z</kbd>, как любая правка.

Кодировка и конец строк показаны в строке состояния; щелчок по ним открывает те же меню.

## Наборы символов

**Кодировки → Наборы символов** содержит все кодовые страницы, включая DOS (OEM-US 437, 737, 775, 850, 852, 855, 857, 858, 860–865, 869) и EBCDIC (037, 500, 1026, 1140). В настройках и командной строке их называют, например, `cp437` или `IBM437`.

## Концы строк

Windows (CR LF), Unix (LF) и Mac (CR) определяются при открытии. Преобразование меняет все строки одним шагом отмены; смешанные концы строк в файле остаются как есть, а режим применяется к новым строкам.
